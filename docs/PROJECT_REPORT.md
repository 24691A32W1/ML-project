# Student Academic Performance Prediction System Using Machine Learning
### B.Tech Mini-Project Report

## Abstract
This project builds a software system that predicts a student's final examination marks from attendance,
study habits, earlier results and related factors, classifies the predicted result into five performance
categories, and highlights students who may need extra academic support. Four regression algorithms (Linear
Regression, Decision Tree, Random Forest, Gradient Boosting) are trained on the same split and compared with
MAE, MSE, RMSE and R². The best model, chosen by 5-fold cross-validation, is deployed in an interactive
Streamlit dashboard. The study uses a **synthetic** dataset of 1,200 records, so the results demonstrate the
methodology rather than real-world accuracy.

## 1. Introduction and problem statement
Institutions often learn that a student is struggling only after the final examination. Earlier indicators such
as attendance, internal marks and assignment completion are available during the semester. A predictive model
can turn them into an early-warning signal so that mentors can intervene in time.

## 2. Objectives
1. Predict final examination marks (regression).
2. Classify students into performance categories.
3. Analyse which factors influence performance.
4. Compare four ML algorithms fairly.
5. Present results in an interactive dashboard.

## 3. Technology stack
Python · Pandas, NumPy · Matplotlib, Seaborn, Plotly · Scikit-learn · Streamlit · Joblib.

## 4. Dataset
* **Synthetic**, generated by `src/generate_dataset.py` (seed 42); 1,200 rows, 13 columns (see data dictionary).
* Generation model: each student has hidden ability and diligence factors that drive attendance, study hours,
  assignments, earlier marks and internal marks. Final marks are a weighted sum of these inputs, a small
  penalty for sleep far from 7.5 hours, and Gaussian noise (σ = 4), clipped to 0–100.
* About 1% of cells in five columns were blanked on purpose to demonstrate imputation.
* The target (`Final_Exam_Marks`) and any derived label are never used as inputs.

Because the generator is largely linear, linear models are favoured. This is a limitation of synthetic data.

## 5. Methodology
### 5.1 Pre-processing
| Step | Method | Fitted on |
|------|--------|-----------|
| Duplicates | `drop_duplicates` (ignoring ID) | n/a (row-level) |
| Missing numeric | Median imputation | training set |
| Missing categorical | Most-frequent imputation | training set |
| Outliers | IQR winsorising (1.5 × IQR) | training set |
| Scaling | StandardScaler | training set |
| Encoding | One-hot (unseen categories ignored) | training set |
| Feature selection | Variance threshold + permutation importance analysis | training set |

All learned steps are inside one `Pipeline`, so cross-validation refits them per fold (no leakage).
Outliers are clipped rather than deleted to keep all records.

### 5.2 Split and validation
80:20 hold-out split with `random_state=42` (960 train / 240 test). Model selection uses 5-fold CV on the
training portion; the test set is evaluated once per model for reporting.

### 5.3 Algorithms
* **Linear Regression** – baseline, interpretable.
* **Decision Tree** – tuned depth and leaf size.
* **Random Forest** – bagged trees, tuned depth and leaf size.
* **Gradient Boosting** – sequential trees, tuned estimators, learning rate and depth.

### 5.4 Performance classification
Predicted marks → Excellent (85–100), Very Good (70–84.99), Good (55–69.99), Average (40–54.99),
Needs Improvement (<40). Average and Needs Improvement are flagged for support.
(The brief was truncated after "Average: 40–"; the remaining bounds are an assumption.)

## 6. Results
| Model | CV RMSE | Test MAE | Test MSE | Test RMSE | Test R² |
|-------|---------|----------|----------|-----------|---------|
| Linear Regression | 4.07 | 3.39 | 17.98 | 4.24 | 0.914 |
| Gradient Boosting | 4.22 | 3.47 | 19.11 | 4.37 | 0.908 |
| Random Forest | 4.30 | 3.66 | 20.72 | 4.55 | 0.901 |
| Decision Tree | 5.24 | 4.51 | 31.22 | 5.59 | 0.851 |

* **Selected model:** Linear Regression (lowest CV RMSE).
* **Category accuracy** on the test set: about 77%; most errors are to an adjacent category, which is expected
  when predictions are off by roughly 4 marks near a boundary.
* **Most influential factors (permutation importance):** Internal Exam Marks, Previous Semester Marks,
  Study Hours, Assignment Score, Attendance. Sleep, age, gender and extracurricular level had almost no effect.
* Figures are in `reports/figures/` (distribution, correlation, model comparison, actual vs predicted,
  residuals, feature importance, category confusion matrix).

## 7. Dashboard
Seven pages: Home, Predict a Student, Batch Prediction, Data Explorer, Model Comparison, Factor Analysis,
About. Single predictions show a gauge, category, approximate 95% range (±1.96 × test RMSE) and rule-based
suggestions.

## 8. Limitations and future work
* Synthetic data: findings do not transfer to real students without re-training and validation on real,
  consented, anonymised data.
* Association is not causation; recommendations are generic rules, not individual diagnoses.
* Fairness: demographic features such as gender should be audited before any real deployment.
* Future work: real institutional data, more features (course difficulty, previous failures), classification
  models, model monitoring, SHAP explanations, database/login support.

## 9. Conclusion
The system covers the complete ML life cycle (data, leakage-safe pre-processing, tuned model comparison,
persistence and dashboard) and shows how early-warning predictions could support students, while being explicit
that its numerical results come from simulated data.
